# 聊天宽度滑块与 Markdown 表格

## 前提

- 使用包含本次修改的页面，准备普通消息和 Plan 均含 Markdown 表格的会话。
- 记录 localStorage 中 `codex-web-local.chat-width-px.v1` 的原值，以便清理时恢复。
- 分别检查浅色、深色主题，以及桌面、375×812、768×1024 视口。
- 本文为手工验收步骤，本轮仅做静态检查，尚未执行页面验收。

## 操作与预期

| 操作 | 预期结果 |
| --- | --- |
| 打开设置，首次查看聊天宽度 | 默认 720 px；滑块范围 640–1920 px、步长 16 px |
| 拖动滑块，在窄、中、宽三个位置停留 | 数值实时更新；消息、Plan、输入框与待发送队列共享最大宽度；实际宽度不超过可用区域 |
| 结束拖动，检查存储并刷新页面 | 新键保存数字字符串；刷新后滑块数值与布局一致 |
| 用 Tab 聚焦滑块，再使用左右方向键和 Home/End | 焦点清晰；按步长调整，且保持在上下界内 |
| 点击“恢复默认”，刷新页面 | 数值和布局均恢复 720 px，刷新后保持 |
| 将新键分别设为非法字符串、空白、2000、801 后刷新 | 分别回落到 720、720、1920、800 px |
| 仅保留旧键 `codex-web-local.chat-width.v1`，移除新键后刷新 | 使用默认 720 px，旧三档不迁移 |
| 在浏览器限制存储的环境中拖动滑块 | 当前页面仍可调整布局，存储异常不打断操作；刷新持久化依赖存储可用 |
| 查看普通消息和 Plan 中下列表格 | 行列分隔线清晰；表头、内边距正常；单元格顶部对齐；显式左、中、右对齐仍生效 |
| 增加多列表格和长 URL，缩小视口 | 长内容可折行；列宽不足时在表格内部横向滚动，页面整体不被撑宽 |
| 在浅色、深色主题重复上述表格检查 | 背景、文字、边框可辨识，深色页面无突兀浅色表格 |

```markdown
| 项目 | 说明 | 状态 |
| :--- | :---: | ---: |
| 短内容 | 这是一段足够长的中文说明，用来观察折行后是否仍保持顶部对齐以及行列分隔线是否连续。 | 完成 |
| 长链接 | https://example.com/a/very/long/path/with/many/segments?query=abcdefghijklmnopqrstuvwxyz0123456789 | 待处理 |
| 第三行 | **强调内容**与普通文本 | 进行中 |
```

## 清理

恢复新存储键的原值（原先不存在则删除），刷新页面；恢复原主题及视口。删除仅为验收创建的会话。
